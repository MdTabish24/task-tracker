  Technical expectations:
  - Layered structure: route -> controller -> service -> repository.
  Controllers thin, business rules services mein, SQL sirf repositories mein.
  Parameterized queries only, ORM ki zaroorat nahi.
  - Zod schemas se request validation middleware level pe (body, params,
  query), aur env vars bhi startup pe Zod se validate ho, missing config pe
  fail-fast.
  - Auth: bcrypt (cost 12), JWT short expiry, ek authenticate middleware.
  Authorization ownership-scoped queries se ho (WHERE user_id = $1 har query
  mein) taaki IDOR possible hi na ho. Doosre user ki resource pe 404 de, 403
  nahi, taaki resource enumeration na ho.
  - Auth endpoints pe rate limiting, helmet aur strict CORS allowlist.
  - Timer server-authoritative ho: started_at aur ended_at TIMESTAMPTZ (UTC)
  mein. Elapsed client pe started_at se derive hoga, toh refresh pe bhi sahi
  rahega.
  - Ek user ka ek active timer DB level pe enforce kar: time_logs pe partial
  unique index (user_id) WHERE ended_at IS NULL. Start pe agar active timer hai
  toh 409. Stop idempotent-safe ho (already stopped pe 409, crash nahi).
  - Start/stop aur delete jaisi multi-step operations transaction mein.
  - Daily summary ek aggregate query se (SUM, GROUP BY task), day boundary user
  ki timezone ke hisaab se (client timezone query param se), UTC assume nahi.
  - Ek central error handler: typed AppError, consistent JSON error shape,
  proper status codes (400 validation, 401 unauthenticated, 404, 409 conflict).
  Stack trace production mein leak nahi honi chahiye.
  - SQL migrations plain .sql files mein, ek chhota runner, seed script test
  user ke saath.
  - Supertest se integration tests, sirf critical paths pe: auth, cross-user
  access denial (user A user B ka task na dekh sake), single-active-timer rule,
  daily summary math. Tests bhi lean rakhna.
